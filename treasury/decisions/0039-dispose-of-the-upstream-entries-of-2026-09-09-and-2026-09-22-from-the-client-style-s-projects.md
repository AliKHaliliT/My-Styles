# 0039. Dispose of the upstream entries of 2026-09-09 and 2026-09-22 from the client style's projects

Status: Accepted
Date: 2026-09-23

## Context

Three projects built from the client style, aligned at e069bab, carried six
entries between them, read on 2026-09-22. Two are dated 2026-09-09 against
e069bab and four are dated 2026-09-22 against a0db0a4, and one of the four
stands in all three files. Two are defects about the security block, whose
rules against weak randomness and weak hashing fired on a decorative canvas
and on a hash a wire protocol fixes, each answered with a per-file waiver.
One is an improvement asking where an advisory dismissal lives. Three came
out of a re-alignment held until they were answered: the link-repair proof
planting on a Status line, a clause-colon splice in the console rule's
configuration comment, and the baseline's working-tree sentence failing the
audit where the harness's settings folder exists. Every claim was tested
against the template's own tree before this ruling.

## Decision

- The two waivers. Refused as template changes, and the projects were right.
  The record that adopted the mechanical security rules prescribes exactly
  the narrow, reason-bearing waiver both projects wrote, because a rule that
  asks whether randomness or a hash is trusted with security cannot read the
  file it fires in. Nothing in the template changes, and the entries close
  with the form they already used.
- The advisory dismissal. Kept. The guide asked for writing and named no
  place for it, and the family's own dismissals lived in delivery notes the
  repository never held. Every guide now names the commit message of the
  change that produced the warning, and says a finding printed on every run
  by design was answered by the record that made it so. The records are the
  package seat's 0079, the server seat's 0076, the client seat's 0080 and
  the host seat's 0056.
- The link-repair proof. Kept, and reproduced in every seat by giving the
  adoption rehearsal's child a first own record superseded in the prescribed
  form. Every chooser now skips Status lines and the plants edit the chosen
  line alone, the rehearsal carries the case, and the template's own twelve
  superseded records took the rulebook's link form, which they had never
  used. The records are the package seat's 0077, the server seat's 0074,
  the client seat's 0078 and the host seat's 0054.
- The console comment. Kept. The comment is two sentences now, and the
  project takes the template's bytes at re-alignment, as it does for every
  carried configuration comment. A wording fix under the prose law leaves no
  seat record.
- The baseline sentence. Kept, and reproduced in the client seat with an
  empty settings folder. Testing it in the package seat found a second
  defect the report could not have seen. The Python audits stripped the
  characters dot and slash one by one from a token's front, so no dot-rooted
  path had ever been judged. Every audit now reads a token the ignore file
  covers as prose, the Python audits drop only a leading `./` or `/`, and
  the rulebooks say so. The records are the package seat's 0078, the
  server seat's 0075, the client seat's 0079 and the host seat's 0055.

## Consequences

The three projects delete all six entries at their next re-alignment and
take the template's form where one changed. The held re-alignments proceed
against a commit that carries every fix. Each of the four law changes landed
through its own branch with its own records, and this ruling is where a
project finds that its entries were read.
