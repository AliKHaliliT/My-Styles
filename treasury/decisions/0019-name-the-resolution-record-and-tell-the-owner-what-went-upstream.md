# 0019. Name the resolution record and tell the owner what went upstream

Status: Superseded by 0020
Date: 2026-09-08

## Context

The owner found a project's resolution record by opening its upstream folder,
and had been checking by hand whether any project had filed anything. The law
made a child write reports and resolutions and never made it announce them,
fixed no cadence for a report in work after the refactor, and gave the
resolution record a place without a name. A second reading of the host rule
also left room to file the bundled letter at the host as a record.

## Decision

A report is written in the same change that closes the work which produced
its entries, an entry is held in STATE only between the workaround and that
close, and the closing note of every delivery names each report written by
path and each entry still held, or says there are none; every delivery gate
holds it. The resolution record is named
`YYYY-MM-DD-resolution-short-kebab-title.md`. In the host seat, the letter
that bundles arrow reports is not a record and is filed nowhere. A
mechanical signal was refused, since whether an agent told its owner is not
a fact a tree holds. Each style carries its own record of the rule.

## Consequences

The owner learns of upstream traffic from the closing note rather than from
the folder, and the folder reads the same in every project.
