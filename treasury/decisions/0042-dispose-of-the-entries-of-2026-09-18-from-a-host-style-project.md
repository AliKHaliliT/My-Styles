# 0042. Dispose of the entries of 2026-09-18 from a host-style project

Status: Accepted
Date: 2026-09-30

## Context

One project built from the host style, carrying an arrow of each of the
three artifact styles, sent the upstream files of its host and its three
arrows. The server arrow reports nothing open. The other three hold six
entries, every one pinned at the family's 6dab73e of 2026-09-18, while
their aligned lines name a commit the family's history does not hold, so
the alignment they claim could not be verified and is the project's to
explain. Every entry was tested against the template's tree at 770e20b
before ruling.

## Decision

- The spelling advisory reads untracked artifacts, from the package arrow
  and the host with one measurement of 48 findings against 1,173. Kept.
  Every docs audit keeps a finding only on a path git tracks. The package
  seat's 0085, the server seat's 0083, the client seat's 0086 and the host
  seat's 0068.
- A function imported by name from the Node HTTPS module escapes the
  loopback refusal, from the client arrow. Kept in part, reproduced on the
  template's bytes. The setup starts the server as it loads and
  synchronizes the built-in module's exports after it starts and after it
  closes, and a suite proves both entrances; the catch-all handler the
  project added is refused, since the refusal already reaches the caller's
  error event and the handler would make it silent. The client seat's
  0087.
- The subprocess heuristic's exception contract, the constructed argument
  lists and the guarded URL opener, three entries from the package arrow.
  Kept as one sentence in the ruff configuration of the three Python
  seats, which states that these heuristics stay in the gate, that a
  literal argument list needs nothing, and that a reviewed site answers
  them with a suppression naming the code with its reason beside it.
  Making them advisory is refused, and literal spelling is not required.
  The package seat's 0086 and the server seat's 0084, the demo arrow
  inheriting the package seat's.

## Consequences

The project deletes the six entries at its next re-alignment, takes the
setup's form and the audit's, drops or keeps its catch-all handler as its
own decision, and meets the suppression contract in the file that
enforces it. An aligned line naming a commit outside the family's history
is a defect in the project's own file, and the next re-alignment writes
the commit it actually took.
