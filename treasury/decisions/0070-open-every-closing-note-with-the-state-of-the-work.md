# 0070. Open every closing note with the state of the work

Status: Accepted
Date: 2026-11-24

## Context

The style's owner reported that with work of several steps, above all
work that runs for a while, a closing note did not always show whether a
task had finished, and asked for a clear signal of the state of the
work. The guides name the closing note in three rules, each fixing one
thing it carries, and none says how a note states where the work stands.

## Decision

- Every closing note, the message that ends or pauses a task, opens with
  one state line in one of three forms, Done with nothing pending or
  with what someone else still holds, Waiting on you with what the work
  needs from the owner, or Running with what is still going and a
  promised report. An answer that only reads and explains carries none.
- It is shared law, so the rules of conduct carry it in every seat, held
  in review. The package seat's 0136, the server seat's 0144, the client
  seat's 0136 and the host seat's 0131.

## Options considered

- A check of the state line. Refused, because no tool can read a closing
  note.
- Listing every step the task took. Refused, because the length buries
  the state and a self-report of steps proves nothing.

## Consequences

A worker in any seat opens its closing notes the same way, so the owner
reads the state of any task in the family from one line. A project
re-aligning to this commit takes the rule with the rest of the rules of
conduct.
