# 0017. Carry the template's records in an inherited folder and start a project's own at one

Status: Accepted
Date: 2026-09-08

## Context

The inquiry project that sent the second upstream report re-aligned to the
records this family added and found that Keel's newest numbers were already
taken by its own records. A child's decision folder had been two sequences
with two writers, the template's carried records and the child's own
continuing the count, so a collision was guaranteed once the template grew
weekly, and the audits' duplicate-number check told the child to renumber the
newer record, which under a mirror is the wrong answer. The adopting agent
offered an offset for the child's numbers, renumbering at every
re-alignment, or a separate folder for the child's own records, and paused
for the style. The owner ruled for the correct path over the cheap one.

## Decision

A project built from a template carries the template's records whole in an
`inherited/` folder under `docs/`, byte-identical at the pin, recopied as one
folder at re-alignment, registered by one row, and never edited or added to.
`docs/decisions/` means the same thing in a template and in every child, this
project's own decisions from 0001, the adoption first. A record cites an
inherited one across the folder. The audits hold both as numbered record
folders with unique numbers within each; the family audit holds the demo
arrow's inherited folder as Keel's whole and stops the carried guide tail
before the index, which lists a project's own documents; the adoption gate's
pin item requires the inherited folder to hold the pin's records whole. In
the host seat each arrow carries its style's records in its own inherited
folder. The offset was refused because existing children would have edited
record bodies to renumber, which the immutability check rightly forbids, and
because a number range carrying jurisdiction is a convention a reader must
know. Each style carries its own record of the rule.

## Consequences

Children born before the rule move their inherited records once, as pure
renames, and keep their own numbers. The template grows for as long as it
lives without colliding with anyone, and whose record a reader holds is
visible in the tree.
