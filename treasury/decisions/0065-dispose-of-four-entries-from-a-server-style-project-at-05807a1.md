# 0065. Dispose of four entries from a server-style project at 05807a1

Status: Accepted
Date: 2026-11-19

## Context

One project built from the server style holds four upstream entries in
its upstream file, all dated 2026-11-19 and filed as defects, pinned at
the family's 05807a1, which the family's history holds. The style's
owner read the file and pointed the work at the template, as the
reporting rule provides. Each entry was tested against the template's
tree at that commit before ruling, and each was real against the
template's own law or its own toolchain. Two concern the template's
bytes. Two concern a worker the law had not considered, a hosted agent
session, whose remote refuses the deletion of a branch and whose working
tree is rebuilt from the repository.

## Decision

- A check constraint declared inside a column, from the server style.
  Kept, in the entry's form. A migration generated from the models
  carries a table's constraints and passes over one a column holds, so
  the database a deployment builds accepted a status the model refuses.
  Both exemplars declare the check on the table under a name, and a test
  fails while any column holds a constraint of its own. A test that
  generates a revision and compares the two databases refused, and it
  reopens when a generated revision passes over a second form. The
  server seat's 0133.
- A remote that refuses a branch deletion, from the server style. Kept,
  in the entry's form, and widened to every workflow of the family. The
  landing step failed any branch merged into main, so it failed one
  standing at main's own commit, the state a worker leaves whose remote
  refuses the deletion, and one made and not yet committed to. The step
  now fails a branch main has moved past and passes one at main's own
  commit, and the rules of conduct say where such a worker leaves its
  branch. Passing branches by their names and deleting them from the
  workflow refused. The package seat's 0128, the server seat's 0134, the
  client seat's 0124 and the host seat's 0124.
- A private ledger in a tree that does not persist, from the server
  style. Kept, and stated for every seat. Where the working tree does
  not outlive the session no private ledger is created, the worker puts
  the fact to the owner, and the owner keeps it outside the repository.
  Copying the ledger out after every change refused, since a sending is
  the owner's. The package seat's 0129, the server seat's 0135, the
  client seat's 0125 and the host seat's 0125.
- The workflow's header saying its actions ride version tags, from the
  server style. Kept, and widened to the five workflows that carry the
  sentence. Every action in every workflow has been pinned to a commit
  since 2026-10-06 and the docs audit refuses a tag, so the sentence is
  replaced by one that says so. The sentence was carried law under
  treasury 0008, which chose tags for the workflows a project copies.
  That ruling is superseded here, since the seats' records of that day
  decided for the digest and no ruling had said so. The package seat's
  0130, the server seat's 0136, the client seat's 0126 and the host
  seat's 0126.

## Consequences

The project deletes the four entries at its next re-alignment and takes
the templates' forms, and its own records on the two cases of a hosted
session stand as the history of how they were first met. No workflow in
the family now says of its actions what the docs audit refuses.
