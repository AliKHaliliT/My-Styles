# 0046. Dispose of five issues from projects built from three styles

Status: Accepted
Date: 2026-10-09

## Context

One maintainer of projects built from the package, server and host
styles sent five entries as issues on the family's repository, the
first use of that channel, each in the upstream entry's own shape and
pinned at the family's b8750ef, which its history holds. Each entry
was tested against the template's tree at that pin before ruling,
and all five were real against the template's own law.

## Decision

- The host selftest's legal claims colliding with a populated ledger,
  issue 1. Kept. The legal plants and the verified pair take their
  numbers from the free-number helper when the proof runs. The host
  seat's 0075.
- Python analyzer targets lacking stack binding markers, issue 2.
  Refused as a marking and kept as law. Both seats' exemplars name a
  class in its own annotations unquoted, which only 3.14's deferred
  annotations allow, so the floor is the style's, said beside each
  version line. The package seat's 0096 and the server seat's 0098.
- An optional showcase path treated as required, issue 3. Kept. The
  baselines name the image's home as a pattern the path check reads
  as prose. The package seat's 0095, the server seat's 0097 and the
  client seat's 0092.
- Namespace grouping hiding modules from the import graph, issue 4.
  Kept as a rule rather than a workaround. A bare grouping directory
  below a door is named as an import-linter root of its own, the
  coverage finding names that remedy, and the selftest plants the
  hidden layout; the empty doors are refused. The package seat's 0097
  and the server seat's 0099.
- The application boot exemplar not entering the lifespan, issue 5.
  Kept. The boot test enters the client so startup and shutdown run
  around its request. The server seat's 0096.

## Consequences

The projects delete the entries at their next re-alignment, and the
issues are closed naming the records above.
