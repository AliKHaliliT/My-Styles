# 0062. Dispose of the entry of 2026-11-06 from a host-style project

Status: Accepted
Date: 2026-11-09

## Context

One project built from the host style sent one upstream entry as an
issue, the twenty-third on the repository, pinned at the family's
d140225, which the family's history holds. The entry was tested against
the template's tree at that commit before ruling, and it was real
against the template's own law. The host's record 0081 holds the date an
extension starts from before the prior pass's Date line, and the check
read every document a Slice links as a prior pass, so a document with no
Date line was given the earliest date there is and failed an overlap
that was sound. Planted at the pin, a bibliography linked beside a prior
pass with a sound overlap was refused, and the same link alone, naming
no pass, drew the same refusal and never the finding that no pass was
named. The defect reached further than the entry saw, since a dated
record of another kind was compared as a pass too.

## Decision

- A document linked in a Slice read as a prior pass, from the host.
  Kept, in the entry's first form. From the extension rule's arrival on,
  only a review record a Slice links is a pass it extends, the
  comparison reads those records alone, and a Slice linking none names
  no prior pass, so the correction loosens nothing. The entry's second
  form, an explicit prior-pass reference, refused, because the reviews
  folder already says which documents are passes, and it reopens when a
  Slice needs to link a review record it does not extend. A pass older
  than the rule keeps its reading. Two plants hold both sides, the one
  the entry asked for among them. The host seat's 0121.

## Consequences

The project deletes the entry at its next re-alignment and may link a
living document in a Slice again from its next pass; the record that
moved the link stands as written.
