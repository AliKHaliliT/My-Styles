# 0103. Refuse an invisible character in a tracked file

Status: Accepted
Date: 2026-10-15

## Context

A bidirectional control can make a line of source read one way to a
reviewer and compile another way, a zero-width space can split a word no
search finds, and a byte-order mark in the middle of a file is a
character no editor shows. Nothing in the package seat refused any of
them; the tree happened to carry none, measured over every tracked file.
A review method the owner keeps outside the family extracts the text of
a finished document and compares it with what is visible, against
instructions hidden for a machine reader, and the question it asks of a
manuscript is one a repository that agents read whole should ask of
itself. Adversary honesty asks that deciding nobody is attacking a
boundary be written down, and this one was not even named.

## Options considered

- A lint rule over source alone. Refused, because the audit already
  walks every tracked text file for the em dash count and a character
  that hides in prose hides in a guide an agent reads as law.
- Leaving it to the secret scan. Refused, because that scan looks for
  credentials and knows nothing of characters.
- Advice rather than a gate. Refused, because the set is closed, a
  code point either stands in a file or does not, and nothing honest
  needs one in a tracked text file.

## Decision

The docs audit refuses an invisible character in any tracked text file,
the bidirectional controls, the zero-width spaces and joiners, the
invisible operators and the byte-order mark, naming the file, the line
and the code point, a generated file apart because it is kept as
written; the check is proven by a planted zero-width space and by a
declared file that raises nothing. The rulebook's Prose section, one
text across the family, says so beside the formatting law, and the root
workflow reads the whole tree once more for the files no seat audits.
The tree held none, so the gate landed green and prevents. The rule took
the strongest form its mistake allows, a check that decides its own
question over the whole tree.

## Consequences

What a reader cannot see cannot reach the tree, and a vendored file or a
pasted snippet that carries one fails on the day it arrives.
