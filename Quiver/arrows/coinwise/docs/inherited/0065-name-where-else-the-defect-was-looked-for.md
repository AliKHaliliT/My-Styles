# 0065. Name where else the defect was looked for

Status: Accepted
Date: 2026-09-16

## Context

A defect found in one place usually has siblings, the same mistake made
where the same pattern was copied, and a fix that repairs the one place
found leaves the others until they fail on their own. The family already
closes this for its mirrored surfaces, where the family audit holds shared
scripts and carried copies byte-identical, so a fix in one is a fix in all
or the gate goes red. Everything outside those surfaces had no rule. The
rulebook reserved the commit message body for the why of one change and
said nothing about where else the change's defect was sought. Treasury study
0005 found the practice stated in the published agent-skills ecosystem as
variant analysis, hunt for the other instances of a bug already found, and
the family disposition, treasury 0030, Take eight rules from the skills
study and refuse the rest, adopted it as one clause on the commit-body rule.

## Evidence

The rulebook's two homes for a why were the commit body, for a why that
explains one change, and the decision record, for a why that would be
re-litigated. A search for the same defect elsewhere is neither; it is a
completeness claim, and the guide's own rule on completeness says such a
claim is a fact only when it names the enumerable list it exhausted, a grep,
a file list, a suite run. The commit body is where that list fits, because it
belongs to the change that ran the search and to nothing after it. The
family's own history shows the practice done by hand. A defect found in one
audit script was fixed in three because the mirror gate demanded it, and a
defect found in one seat's guide was fixed in four by the same instinct with
no rule behind it.

## Options considered

- A STATE entry per search. Refused, because STATE holds in-flight work
  and a finished search is finished; the entry would be deleted in the
  same change that made it.
- A section in the decision record. Refused, because most fixes earn no
  record, and the ones that do describe the defect's cause rather than its
  siblings.
- A check that a fix commit's body carries the clause. Refused under the
  ladder for now, because no check can tell a fix from any other change
  without a convention on commit titles the family does not have, and a
  clause held in review by the commit-message rule already in force is the
  form that binds.

## Decision

The commit-body rule in every rulebook gains one clause. When the change
fixes a defect, the body also names where else the same defect was looked
for and what was found, so the search is a fact a reader can re-derive
rather than a claim that everything was checked. The host rulebook, which
states the two homes in its own words, gains the same clause in its voice.
The arrow carries the rulebook. This rule lands as prose, held in review
with the other commit-message rules, because no check reads a commit body
for a claim's boundary.

## Consequences

A fix commit now carries its search, the grep or the file list and its
result, and a reader who later finds a sibling can see whether it was
missed or was outside the search. Commit messages for fixes grow by one or
two sentences. The mirrored surfaces keep their stronger guard, the gate
that fails when a copy diverges.
