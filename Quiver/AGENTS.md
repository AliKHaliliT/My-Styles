# Quiver Agent Guide

Quiver is a strict, AI-ready template for research-backed projects, demonstrated on a small rounding-drift inquiry. It is a host rather than a fourth peer of the artifact styles. The inquiry layer at the root states an aim, asks its questions, and keeps the claims, and complete instances of the artifact styles live whole under `arrows/`, each governed by its own law. It is a style template and living blueprint rather than a finished research project, so some gaps are intentional and must not be "fixed" unprompted. Here that is the demo arrow, which is deliberately incomplete in the ways its own README names. The permanent gaps are the ones named here; anything temporary appears in STATE.md. This guide, [docs/RULES.md](docs/RULES.md) and [docs/CONDUCT.md](docs/CONDUCT.md) are read to their ends before any work, and so are the rulebook, the gate, the method file, the state file, the map, the ledger and the baseline where the work touches what they govern; a document is read whole, never by its first and last lines, and the index below names every other document and when it is read.

## Commands

- Audit the inquiry: `python scripts/audit_inquiry.py` (the living documents, the questions against the ledger, the claim ledger, the review passes, the citations, and the pins against the tree, the calendar, and git history)
- Prove the audit itself: `python scripts/audit_inquiry.py --selftest` (every rule against a planted defect, because a check that never fires and a check that cannot fire look identical)
- Work on an arrow: use that arrow's own commands, stated in its README; for the demo arrow, `cd arrows/coinwise` then `pip install -e .` with `pip install --group dev`, and its gate commands are `pytest`, `ruff check . && lint-imports`, `mypy src tests`, and `python scripts/audit_docs.py`

The checks report at two levels. A failure is a verdict, it stops the command, and it means a rule the tool fully decides has been broken. A warning is advice, it leaves the exit status clean, and it comes from a check that cannot decide its own question and so is not allowed to gate. Advice is not noise and not optional reading. Every warning is looked at and then either fixed or dismissed in writing in the commit message of the change that produced it, so the judgment outlives the run that asked for it, and a warning is never silenced with a suppression to make a run look clean. A finding printed on every run by design, like a review row of the invariants ledger, was answered by the record that made it so and needs no repetition. The advisory checks here are the stale-pin scan, the audit's vocabulary advisory, which reads an honest domain term the same as a tell and so advises for review, its spelling advisory, which runs where codespell is installed over the files git tracks and no other, reads the project's own terms from `.codespellignore`, and names itself as not run elsewhere, and its form advisory, which counts the references a prose paragraph names and cannot tell an enumeration from an argument, so it advises a list or a table and gates nothing. Its splice advisory names a colon that opens a lowercase clause in a record main does not hold yet, because a list colon and a spliced one look alike to a machine, and it falls silent once the record has landed, since a defect found in a merged record stays. Its depth advisory names each Supported claim whose evidence cites a work no pass has read in full, with the pass that read it, and falls silent when a later pass reads the work whole or the claim names the depth among its threats, because whether a quoted passage came from the work or from its abstract is a fact only the pass record holds. Its standing advisory names each Supported claim whose evidence cites a work standing below the floor the bibliography declares, each Supported claim whose evidence cites a work whose entry says retracted, floor or none, and each preprint not checked for a published version in ninety days, and it falls silent when the claim names the key among its threats, when the check's date moves, or, for the floor alone, when no floor is declared, because whether a blog post may carry a claim is the inquiry's to decide and the bibliography's to show. The stale-pin scan flags every claim still standing as current, its status neither Stale nor Superseded, whose arrow has moved past its pin in the paths that can change a result, the code, the suites and the project files of the style its manifest names, which the scan lists per style. Documentation carried inside an arrow executes nothing during a run, so its movement never advises, and only a person can tell whether a flagged movement touched what the claim measured. The vocabulary grep reads a banned word the same as an honest domain term, which is why it advises and never gates (see the Prose section of [docs/CONVENTIONS.md](docs/PROSE.md#prose)). A check the tree gave nothing to run is named as not run, with what it needs, so a clean verdict never hides a check that never looked.
