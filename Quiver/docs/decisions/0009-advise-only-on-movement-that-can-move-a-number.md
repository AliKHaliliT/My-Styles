# 0009. Advise only on movement that can move a number

Status: Accepted
Date: 2026-08-28

## Context

The movement advisory watched the whole arrow folder, and the same day the
family adopted its mirror gate, which recopies carried Keel bytes into the
demo arrow on every Keel law change, the two settled claims started drawing
advisories again. The commits that raised them touched decision-record
copies, a rulebook copy, and a workflow, bytes that execute nothing during
an experiment, so the advisories asked a person to re-judge evidence that
provably could not have moved. Left alone, that recurs on every future law
change forever, and record 0006 already named where that road ends, in
advisories nobody reads.

## Decision

The advisory watches only the paths inside an arrow that can change what a
run produces, its `src`, its `tests`, and its `pyproject.toml`, the file
that selects dependency versions and warning behavior. That boundary is
enumerable and stated in the scanner, per the family's completeness rule.
Movement anywhere else in the arrow is documentation history and stays
silent. The pin itself keeps its whole-tree meaning; only the advisory's
trigger narrows, so nothing about what a claim asserts or reproduces
changes.

The selftest gains a fourth advisory plant beside the three of record
0006, a Supported claim pinned at the last commit that touched evidence
paths, in a history where the arrow moved afterward in other bytes alone.
It must rest, proving the scan tells the two kinds of movement apart, and
it is skipped with a printed reason when history holds no such commit.

## Consequences

The standing advisories on claims 0004 and 0005 fall silent with no edit
to either claim, because under the narrowed trigger they should never have
fired, the arrow having moved only in carried documentation since their
pin. A change to the rounding code, the suites, or the dependency story
still advises exactly as before. Mirror syncs, prose-law updates, and
every future carried-byte refresh cost the ledger nothing.
