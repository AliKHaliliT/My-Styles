# 0115. Say in the seed row that a mis-chosen seed stands outside Found

Status: Accepted
Date: 2026-10-22

## Context

Record 0108 taught the seeds check a second verdict. A seed the seeds
line marks mis-chosen stands outside Found, and the check fails a mis-
chosen seed Found names as it fails any other seed Found omits. The
record changed the check, the rules for review records and the method,
and left the invariants ledger's seed row as it stood, so the row
promised only the first half, that each seed is a key Found names or
none. A reader took the row to say that a mis-chosen seed absent from
Found fails the check, which the check no longer does. A project built
from this template found the gap when its re-alignment compared the rows
it had cut from the template's against the checks each names as its
holder.

## Options considered

- Leave the row and let the check's docstring carry the second verdict.
  Refused, because the ledger is what a reader takes a holder to
  promise, and a row that says less than its holder decides is the gap
  the ledger exists to close.
- Add a second row for the mis-chosen verdict. Refused, because the two
  verdicts are one check's two sides over one line, and a reader counts
  rows as claims.

## Decision

The seed row says that each seed is a key Found names unless the line
marks it mis-chosen, which Found never names, or that the pass says
none. The holder and the rung stand; a record that changes what a check
decides changes the row that names the check in the same landing from
now on, and this record closes the one that did not.

## Consequences

The row and its holder promise the same thing, and a reader of the
ledger learns the mis-chosen verdict without opening the audit.
