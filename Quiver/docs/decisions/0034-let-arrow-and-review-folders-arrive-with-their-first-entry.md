# 0034. Let arrow and review folders arrive with their first entry

Status: Accepted
Date: 2026-09-10

## Context

The family's first adoption rehearsal built a fresh inquiry from this
template, one with a question, one conjecture, no arrow, and no pass over the
literature, and the child could not pass its own audit. The rulebook's spine
table named the review folder and the arrow folder as paths every project
carries, the guide and the map named the review folder the same way, and a
project that has not yet run a pass or written an arrow has neither folder,
because git holds no empty folder. The two real projects built from this
template never met the failure, since both arrived with arrows and passes;
the rehearsal met it on its first run, which is what it exists for.

## Decision

The review folder and the arrow folder join the spine with their first
entry. The rulebook says so in place of the two spine rows, the guide and the
map name the folders as folders under docs rather than as paths the tree must
hold, and each is registered by its own index row when it appears, the way
the upstream file's row is. A fresh inquiry carries the question, its
conjectures, its decisions, its bibliography, and nothing it has not yet
done. The selftest, which plants into those folders, builds the ones the
tree lacks before it plants and removes them once every plant is gone, so
it proves the rules in a project born empty as well as in the template.

## Options considered

- A placeholder file to make the folders exist was refused, because a file
  that says nothing is exactly the kind of tracked byte the family forbids.
- Exempting the spine table from the path check was refused, because the
  check is right to insist that a path a document names exists; it was the
  rulebook that named a path it should not have.

## Consequences

A project can be born empty and pass. The rehearsal keeps building the fresh
inquiry, so the next sentence that names a folder a young project lacks fails
here before it fails there.
