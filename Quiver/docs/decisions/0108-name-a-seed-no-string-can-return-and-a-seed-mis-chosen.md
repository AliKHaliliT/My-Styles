# 0108. Name a seed no string can return and a seed mis-chosen

Status: Accepted
Date: 2026-10-21

## Context

A pass fixes seeds before its strings and tests the strings against
them. The review rules said an indexed seed the strings missed is named
with the word the string lacked and the corrected string as a new run;
the method said a string searches title, abstract and keywords and never
full text, and that a string passes when it returns every indexed seed
or the Boundary names the seed it missed and why the pass went on. A
project built from this template fixed a seed whose indexed fields hold
no word of the slice's concept, met the first rule by running the string
over full texts, read the method's ban afterward, withdrew the run, and
found that the seed itself failed the criteria once read whole; the law
had no word for a seed mis-chosen, so Found named a work the pass had
excluded. The demo's own pass had already named two such misses with the
fields that lacked the word and gone on, under the method's branch and
against the review rules' letter.

## Options considered

- A full-text run to recover a missed seed, declared and counted apart.
  Refused, because a full-text hit is a work that mentions the concept
  once, so the run tests nothing about the string and floods the funnel
  with works no string of the method would return.
- Leaving the review rules' letter and reading the method's branch into
  it. Refused, because two frozen files that disagree are read by an
  agent as a choice, and this one chose the run.

## Decision

The review rules take the method's branch. An indexed seed the strings
missed is named with the word the string lacked and the corrected string
as a new run, or, where its title, abstract and keywords hold no word of
the concept or the lacking word would flood the result, with those
fields quoted and why the pass went on. A seed that fails the criteria
once read in full was mis-chosen; the seeds line marks its key `(mis-
chosen)`, the Boundary names the criterion it failed and the log holds
its exclusion, its miss is charged to no string, and Found does not name
it, because Found is what the pass entered. A run made outside the
method is withdrawn and named in Left out with its index, its count and
why, and nothing it retrieved is kept outside the record. The audit
holds a mis-chosen seed outside Found as it holds every other seed
inside it, with a plant for each side.

## Consequences

A seed the index describes under another task costs the pass a sentence
and not a run, a mis-chosen seed is written as the error it was, and a
pass never enters a work it excluded. The project's record stands as
written, since a record admits no edit, and its next pass takes the
form.
