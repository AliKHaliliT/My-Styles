# 0072. Leave a file a machine wrote outside the em dash count

Status: Accepted
Date: 2026-10-06

## Context

The prose law budgets two em dashes per tracked file and the docs audit
counts every tracked text file outside the inherited folder and the arrows,
judging a record only from the rule's arrival because a record admits no
edit. A recorded claim names the artefact it preserved by
path, and the audit holds that path to exist; nothing in the law let it
be edited, and nothing put it outside the count. A project built from the host style reported on
2026-10-06 that a report a hosted model wrote, preserved whole for a
recorded claim, carried 64 em dashes the project never chose, that a
second carried 22, and that neither could be edited under the budget
without ceasing to be the evidence. It kept both by writing each em dash
as the JSON escape, a lossless change a format without escapes could not
make, and asked whether the template meant preserved artefacts to be
held.

## Evidence

Measured on 2026-10-06. The host audit counts every tracked text file
outside the arrows and the inherited folder, and the host's law on
recorded evidence names an artefact by path and holds it to exist, which
leaves the two rules no tree that keeps such an artefact whole once its
author's prose runs past two. This template's own
tree holds no preserved artefact, so the count was zero by absence. No seat's attributes file
declared any file as written by a machine, and git reports such a
declaration for every tracked path in one call.

## Options considered

- Exempting a folder of preserved evidence, as the project proposed.
  Refused, because the template names no such folder, a project's name
  for it would differ, and the package seat's recorded fixture lives
  under its tests.
- Counting only files a person writes. Refused as stated, since no check
  can tell the author of a byte; the declaration below is what makes the
  question decidable.
- Requiring every artefact a `Recorded:` line names to carry the
  declaration. Refused for now, because the count already fails on such
  an artefact at the one moment it matters and its finding now names the
  way out.

## Decision

The prose law binds prose a person writes for the project. A file a
machine wrote and the tree keeps as it was written, a recorded fixture or
a preserved report, is declared `linguist-generated` in `.gitattributes`,
the attribute GitHub reads to fold such a file in a diff, and the docs
audit's em dash count and spelling advisory leave a declared file alone.
The count's finding names the declaration as the way out. The
rulebook's claims section says that an artefact a `Recorded:` line
names is declared so.
The selftest plants a declared file over the budget that must stay
silent beside the undeclared one that must not.

## Consequences

Evidence stays as observed and the budget keeps binding what a person
writes. The declaration is one reviewable line, so a file declared to
dodge the count is visible in the change that declares it.
