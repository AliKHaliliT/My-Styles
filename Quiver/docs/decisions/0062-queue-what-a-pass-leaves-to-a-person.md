# 0062. Queue what a pass leaves to a person

Status: Accepted
Date: 2026-09-29

## Context

A pass run by an agent ends where its access ends. A publisher refuses the
fetch, a database sits behind a library login, a verification needs the
full text of a work read at abstract depth. The pass record's Left out
section names what the boundary excluded, and the state file's Blocked
section holds work waiting on something external, and no rule joined the
two, so what a pass needed from a person lived in the writer's memory and
in whatever the closing note happened to say. A literature review run
outside this template on 2026-09-28 ended each pass with a hand-written
list of the same needs, and its author asked how the list would survive the
session that wrote it.

## Evidence

On 2026-09-29 this inquiry's second pass named in its Left out a regulation
the tooling could not fetch, and the state file said nothing was blocked.
The queue existed and the item was not in it. The audit already holds every
Blocked entry to a ninety-day horizon and fails one that stands unchanged
for two, under record 0030, Hold a queued entry to two horizons of
unchanged text, so a queue that a pass writes into is a queue that cannot
rot quietly.

## Options considered

- A needs section inside the review record. Refused, because a record is
  immutable and a queue is swept; the record keeps the account of what was
  left and the living file keeps the queue.
- An audit check joining Left out to Blocked. Refused, since both are
  prose and no tool decides whether a sentence names a blocked source; the
  horizon on Blocked is the check that exists, so the rule lands as a
  sentence and a gate item, the strongest form its mistake allows, and this
  record says why no stronger one was available.
- A separate needs document. Refused, because execution tracking lives in
  the state file and nowhere else by the rulebook, and a third place for
  work is a place nobody sweeps.

## Decision

A pass names in its Left out each source it could not open, each search it
prepared but could not run, and each verification it needs a person for,
and queues each as a dated entry in the Blocked section of the state file,
naming what it waits on and why. A later pass that resolves an entry
deletes it. The delivery gate gains the item that every such need is
queued and that the closing note names each entry by its text, or says
there is none. The rulebook's Left out bullet and state rules, the guide's
pass section and gate, and the map's pass paragraph carry the rule. The
demo's queue holds its first entry, the regulation its second pass could
not fetch, dated the day the pass ran.

## Consequences

A person reading the state file sees what the inquiry needs from them
without reading the passes, and the audit's horizon turns a fetch nobody
made into a red run after ninety days and a refusal after two horizons
unchanged. The demo's entry is the owner's to resolve, by reading the
regulation and handing its text to the next pass over the slice, which
then deletes the entry.
