# 0126. Say in the workflow that its actions are pinned

Status: Accepted
Date: 2026-11-19

## Context

Each seat's workflow opened with a sentence that its actions ride
major-version tags so a child of the template starts current, with an
invitation to pin them when its threat model warrants. A family ruling
of 2026-08-28 chose that split, tags for the workflows a project copies
and digests for the family's own. On 2026-10-06 every seat pinned its
actions to commits and gave the docs audit a check that refuses a tag,
and the sentence stayed where it was. So the head of the file described
a form the tree no longer permits, in each of the four seats and in the
host's demo arrow, and a project that copied the workflow copied the
sentence with it. One did, replaced it in its own copy, and sent the
case as an entry.

## Evidence

Read on 2026-11-19 over the family's eleven workflows. Every reference
to an action, forty-five in all, names a commit of forty hex characters
with its version beside it, and the sentence stood at the head of five
of them.

## Decision

The sentence is replaced in the five workflows by one that says what the
file does, that every action is pinned to the commit it runs with its
version beside it, because a tag is a name that moves, and that the docs
audit refuses anything else. The family ruling that chose tags is
superseded in the treasury by the ruling that disposes of the entry,
since the seats' records of 2026-10-06 had already decided for the
digest and no ruling had said so. No check is added. A sentence in a
comment is prose, and what the comment now says is the rule the audit
already holds.

## Consequences

A project that copies a seat's workflow reads at its head the rule its
own audit enforces. The trade the old ruling weighed, a digest that ages
against a tag that moves, stays decided for the digest, and a project
moves an action to a new release by changing a commit and its comment
together.
