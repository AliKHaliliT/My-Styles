# 0113. Name whose record a bare citation means

Status: Accepted
Date: 2026-10-20

## Context

A registered document of the server style, the README of its engines
directory, cited a record by its number alone, "decision 0009", and a
project built from the style read the number against its own records and
found an unrelated decision, because the style's records travel into a
child as the inherited folder while the child's own count from one. The
rulebook asked for a record's number and title beside a link, and the
carried law already wrote "the style's record 0003" where no link could
hold in both trees, but no sentence said how a document that travels
should cite, and the audits held only the linked form, so a bare number
passed every seat. The same form stood in the two Python seats' tool-
configuration comments, which re-alignment recopies, and in two test
comments.

## Options considered

- A link into the decisions folder beside the title. Refused, because no
  relative link resolves in the template and in a child alike, so a
  child would repair every copy at adoption.
- Fix the one sentence and leave the form to review. Refused, because
  the child could not tell whether other documents did the same, and
  neither could review, while a bare number is decidable.

## Decision

A record cited where no link can stand names whose record it is, the
style's or this project's own, beside its number and its title, and the
docs audit fails a living document or a tracked configuration that cites
a record by its number alone, reading an owner word before the number or
a link around it, with the files the vocabulary advisory skips as
quoting ground. The engines README, the two configuration comments and
the two test comments take the form, and the selftest plants a bare
citation.

## Consequences

A citation reads the same in the template and in every project built
from it, and a bare number is a finding before it reaches a child.
