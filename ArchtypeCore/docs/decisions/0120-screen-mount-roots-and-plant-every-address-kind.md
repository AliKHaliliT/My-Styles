# 0120. Screen mount roots and plant every address kind

Status: Accepted
Date: 2026-10-22

## Context

An upstream entry is written to leave the repository, so every seat's
audit refuses one that carries an address, a URL, an email or an
absolute path, and the records that made the rule said a plant stands
for each kind. The matcher knew absolute paths by a fixed list of roots,
and the list lacked the roots mounted storage takes, Volumes on one
system and media on another, so a path under either passed as prose. The
selftests planted a URL and a home path and nothing for an email, a
drive path or a mount root, so the plants said less than the records. A
project built from the family measured the matcher against six tokens at
its re-alignment and found the two mount-root paths unmatched.

## Options considered

- Treat every token that opens with a slash as an absolute path.
  Refused, because a route, a URL path and a fraction open the same way,
  and an entry about an endpoint would be refused for naming it.
- Leave the roots and the plants and keep the rest with review. Refused,
  because the records promised a plant per kind, and a promise the
  selftest does not keep is the kind of drift the family refuses.

## Decision

The matcher's roots gain the mount roots, media, Volumes, private and
run, beside the ones it knew, in every seat's audit alike. Each selftest
plants an email, a drive path and a path under each of the two mount
roots beside the URL and the home path, so the plants match the rule's
four kinds and the roots the rule names. A name stays with review, as
the records said.

## Consequences

An entry that names a path on mounted storage is refused before it
leaves, and the plants now say what the records say.
