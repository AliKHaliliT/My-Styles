# My Styles

![License](https://img.shields.io/github/license/AliKHaliliT/My-Styles) ![Last Commit](https://img.shields.io/github/last-commit/AliKHaliliT/My-Styles) ![Open Issues](https://img.shields.io/github/issues/AliKHaliliT/My-Styles)

A family of templates for software a person and an agent build together, four so far: a server, a package, a client and a research host. Each template ships its law as bytes an audit checks, every decision as a dated record that is never edited, and a selftest that proves the audit against planted defects. It is not a framework and not a generator. A style is copied whole into a project and adopted, and what the project learns flows back here.

## The ideas

- **The demo is the exemplar.** Every artifact a project needs is cut from a file that already exists in the template, because a rule names what must exist and only bytes carry how it reads.
- **The rulebook is frozen and owned here.** A project never edits its copy; a case for changing a rule travels back as an entry.
- **Records are immutable.** A decision is written once, dated, and superseded by a new record when reality moves. A defect found in a merged record stays, because a record is evidence of its day.
- **A check decides only what it can.** Everything a tool cannot decide is named as review's work beside the rule, so a green run never claims more than it proved.
- **Every rule has a plant.** Each audit proves itself by planting the defect each rule refuses and watching it fire, because a check that never fires and a check that cannot fire look identical.
- **Prose has a law.** Every tracked byte is written for a public audience, with a budget on em dashes, a ban on hedges and theater, and a spelling and vocabulary advisory in the gate.
- **The road runs both ways.** A project built from a template keeps one living file of what it learned, and the template's rulings on every entry are public here.

## The styles

| Style | What it is | Demonstrated on |
| --- | --- | --- |
| [ArchetypeCore](ArchtypeCore/) | A strict Clean Architecture template for backend services, bound to no framework: unit of work, repositories, ports, and a core no framework reaches. | A VPN device-management service, served through FastAPI. |
| [Keel](Keel/) | The same boundaries in library form, a hexagonal template for installable Python packages with a src layout, plugin entry points and a typed facade. | An offline agent engine. |
| [Helm](Helm/) | A template for client-side web applications: one-way sliced layers after Feature-Sliced Design, a schema-checked wire boundary, and the server cache kept apart from client state. | A harbormaster console. |
| [Quiver](Quiver/) | A host template for research-backed projects: an aim over numbered questions, a claim ledger with evidence pinned to commits, review passes with records, and complete instances of the other styles vendored as arrows. | A rounding-drift inquiry. |

The family grows one style at a time. Each arrives the way these did, designed from the treasury's studies before a line of its demo is written, and the next one is drafted the same way.

## Starting

Copy one style's folder whole into a new repository, open its `AGENTS.md` and read it to the end. It is the single entry point for a person and an agent alike: the commands, the hard rules, the delivery gate, the documentation index, and the adoption refactor that brings the project under the law. The template's own records come along in an `inherited` folder, and the project writes its own from number one. When the template moves, the project re-aligns to the new commit and resolves what it had sent.

## How the family keeps itself honest

The root workflow runs on every push. Each style's gate runs in its own job, its selftest first and then its audit, lint, types and tests. A family audit holds the blocks of law the styles share as one text and every carried copy byte-identical to its original, and holds the treasury's index of shared names to its studies. An adoption rehearsal builds a project from each template, shaped the way adoption shapes it, and requires its gate to pass there too, because a check proven only in the template is proven where its preconditions are absent. The em dash budget, a secret scan and the tooling's own lint and types run beside them.

## Feedback

Anyone holding a project built from a template holds the family's feedback, and the right move is to file each entry as an issue here, from the [upstream entry template](.github/ISSUE_TEMPLATE/upstream-entry.md). An entry is dated, pinned to the template commit it was written against, and names nothing that identifies the project. No reply is owed; every entry is tested against the template's tree, and the ruling is a public record in the treasury that the project resolves against at its next re-alignment.

## The treasury

The [treasury](treasury/) holds research findings that no single style owns, recorded so each new style is designed from evidence rather than from memory. One study per folder, the research record before the findings, one living table of the names more than one study holds, and the family's rulings in its decisions folder.

- [Study 0001](treasury/0001-primitive-reduction/) reduces 14,765 named software engineering concepts to the 125 primitive operations underneath them.
- [Study 0002](treasury/0002-optimization-vocabulary/) sweeps the vocabulary of optimization into 1,272 priced entries.
- [Study 0003](treasury/0003-security-vocabulary/) does the same for security, 1,996 entries, each a cost a threat model decides whether to pay.
- [Study 0004](treasury/0004-research-methodology-vocabulary/) names 2,908 entries of research methodology, the ground the host style was built on.
- [Study 0005](treasury/0005-agent-skills/) reads the agent-skills ecosystem against the family's law and takes eight rules from it.
- [Study 0006](treasury/0006-invariant-binding/) asks how a stated invariant is bound to something that holds it, and gave every style its invariants ledger.

## Why it exists

This began as a reference for how one person works, a set of styles to show how I build and what I hold a codebase to. It became the system itself: a growing family of styles that teach one discipline to a person and an agent alike, an audit for each that proves its own rules, and a record of every decision along the way. It is still one person's work, and every byte of it is written to be read by strangers.
